## 2. 턴 버퍼 실측 (디버그 브리지 + `diag/dbg_framelog.py`)

- 매 사이클 턴 버퍼 길이(0x654AA0)·앞 48바이트, 상한(0x57F0D8 = 496), 지연(0x6556E4)을 기록.
- 싱글·LAN 모두 **매 프레임 턴**이 나가고 명령 지연은 **3사이클**. 매 턴 맨 앞에 게임이 넣는 Sync(0x37) 7바이트가 있다.
- MSQC 패킷 = `09 01 QC` + `15 x x y y 00 00 E4 00 06 00` (Move). 키 비트는 기준 (64,64) 에 더해진다.
- **원인 발견**: 게임 프레임 % 150 = 8 인 사이클마다 받는 쪽 값이 빈다 (LAN 150초에 34번, 두 플레이어 모두).
  그 순간 QC 유닛의 오더 상태(+0x4E)가 0 (78번 중 77번) → **스타가 150프레임마다 QC 유닛의 Move 를 다시 시작시킨다.**
- 곁가지: CUnit+0x74(오더 큐 머리)를 감시하려다 EUD ERROR 0xFF9E0813 (= ~0x0061F7EC). SC:R 이 막는 칸.

## 5. 구현 (2026-09-17)

제작자 요청: "DPS강화하기의 eudplib 판과 기존(CtrigAsm) 판 중 무엇이 나을지 실측 전이라 둘 다 필요" → 두 판을 만들었다.

- **`SNQC.py`** - MSQC.py(eudplib 0.76.14 에서 동작)의 설정 해석부를 그대로 가져와 줄 문법을 맞추고, 채널을 랠리 방식으로 바꿨다.
  - 채널 건물 생성(사람 소유 → P11 에 넘김 → 소유자 바이트 되돌림 → 무적·충돌 없음), 없어지면 다시 만들기(`QCDebug`).
  - 키 비트 배치를 맵 크기에 맞춰 넓힘 (192×96 에서 21 → 23비트, 256×256 에서 26비트). 값은 x 에 1 을 더해 기준값 (0,0) 을 피한다.
  - 합치기(Merge): 아직 안 나간 자기 패킷이 버퍼에 있으면 좌표만 고친다 (키 = 비트 합치기).
  - 선택 되돌리기: eudplib 의 `QueueGameCommand_Select`, 아무것도 안 고른 경우 `QueueGameCommand_RemoveSelect` 로 채널을 뺀다.
  - `QCUnit` 이 12종이 아니면(보통 그렇다) 무시하고 106 을 쓴다 → .eds 는 단락 이름만 바꾸면 된다.
- **`SNQC.lua`** - 같은 설계를 CtrigAsm 으로. Lua 함수 설정 + MSQC 줄 문법(`SNQC_Line`). 값 유지(Hold)·새 값 표시(NewDeath)·
  바뀐 값만 보내기(Change) 를 더 넣었다. 작업 공간 주소(`WorkAddr`) 설정 - DPS 는 0x58F500~ 를 CreateVoid 없이 직접 쓴다.
- 시험하며 고친 것: 점검 카운터가 지역 변수로 잡힘, `EUDElse()()` 사용법, 로케이션 번호 기준(eudplib 은 1부터),
  Lua 5.3 의 `2^n` 실수 문제, TEP 의 "정의 안 된 전역 읽기 = 에러"(`loadstring`), 설정 이름 검사.
