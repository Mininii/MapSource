# 마린키우기 황혼협곡 128

`마린키우기_쥬림산맥_2.8_공2배_리밸런싱F4.scx` (256x256 정글) 를 바탕으로,
**지형과 배치를 전부 새로 만든 128x128 트와일라잇 판**을 생성하는 도구 모음이다.

산출물: `out/marine128.scx`
(스타크래프트 `Maps` 폴더에 `마린키우기_황혼협곡_128.scx` 로 복사해 둠)

```
python make.py [seed] [tag]   # 지형 생성 → 로케이션/유닛 배치 → CHK → SCX → 검증 → 렌더
```

기본 시드는 17이다. 시드마다 지형이 통째로 달라지므로 `python make.py 21 v21` 처럼
태그를 붙이면 `out/marine128_v21.scx` 로 따로 나온다.

## 1. 원본 분석 결과

| 항목 | 값 |
| --- | --- |
| 크기 / 타일셋 | 256x256 / Jungle |
| 트리거 | 1663개, **전부 클래식** (EUD 조건·액션 0개) |
| 로케이션 | 255개 (트리거가 246개 참조) |
| 배치 유닛 | 2174개 |
| 문자열 | 448개 (UTF-8, SC:R 방식) |

게임 구조는 **디펜스형**이다.

- 적은 약 120곳의 스폰 로케이션에서 나와 **전부 `hp1` 한 곳으로 Patrol** 한다
  (Order 액션 2435건 중 hp1 이 목적지인 것이 대부분).
- 웨이브 번호는 `Deaths(P1, Terran Vulture#2)` 같은 **죽음 카운터**가 센다.
  난이도별로 카운터 유닛이 다르다 (보통=Terran Beacon, 어려움=Zerg Beacon,
  베테랑=Khaydarin Crystal, 클래식=Protoss Assimilator).
- `CommandLeastAt(P1, Zerg Hive#133, ...)` 는 전형적인 **동점 난수** 관용구다.
- 최종 보스는 `xen` 에 나오는 Tassadar/Zeratul 30기이고, 29~30기를 잡으면 승리.
- 메뉴룸(`T1`,`m1`~`m5`,`player1`,`fast` …)과 보스섬(`xen`,`T4`,`102`,`103` …)은
  **원본에서도 본진과 걸어서 연결되지 않는다.** MoveUnit 텔레포트로만 오간다.

이 구조 덕분에 **트리거·문자열·업그레이드 설정은 한 글자도 건드리지 않고**
지형과 좌표만 새로 만들 수 있었다.

## 2. 새 맵 설계

- **128x128, 트와일라잇.**
- 아래쪽 한가운데에 **요새**(`hp1`)를 두고, 그 둘레에 능선 3겹을 서로 엇갈린
  통로와 함께 배치했다. 바깥에서 요새까지 오려면 좌 → 우 → 가운데로 지그재그로
  내려와야 한다.
- 능선은 **램프 없는 고지대**다. 스타에서 고지대는 걸을 수 있지만 램프가 없으면
  섬이 되므로, 결과적으로 지나갈 수 없는 산맥이 된다.
- 왼쪽 위에 **메뉴룸**, 오른쪽 위에 **보스 아레나**를 절벽으로 완전히 격리했다.
  원본과 같은 역할이다.
- 산·호수·바닥 질감은 값 노이즈로 가장자리를 흩어 손으로 그린 느낌을 냈다.
  바닥은 Dirt 위에 Mud/Rocky/Rough/Flagstone 네 가지 변형을 섞었고(전이 타일이
  100% 통행 가능한 조합만 골랐다), 큰 산 안쪽에는 **최고지대 봉우리**를 넣어
  절벽이 2단으로 보이게 했다.
- 두들레드 160개는 블리자드 공식 트와일라잇 맵에서 뽑은 타일 스탬프를 쓴다.

### 로케이션 재배치 방법

원본에서 각 로케이션의 **`hp1` 기준 방위각과 걸어서의 거리**를 재고,
새 맵에서 같은 방위각 · 비례한 거리에 놓았다. 크기는 절반으로 줄였다.

서로 겹치는 로케이션은 **한 덩어리로 묶어** 상대 위치를 유지한 채 옮긴다
(177개 그룹). 원본은 작은 마커 로케이션을 큰 스폰 사각형 안에 겹쳐 두고
배치 유닛을 양쪽에서 동시에 세기 때문에, 이걸 안 지키면 트리거가 세는 유닛이
사라진다.

| 지표 | 값 |
| --- | --- |
| 거리 오차 (중앙값 / p90) | 13 / 32 미니타일 |
| 방위각 오차 (중앙값 / p90) | 17° / 62° |
| 로케이션 간 최근접 거리 | 원본 8타일 → 새 맵 4타일 |

배치된 유닛은 자기가 속한 로케이션을 따라가고(993개), 나머지는 `hp1` 기준
절반 축소로 옮겼다. 맵 리빌러는 면적이 1/4 이 되어 과밀해지므로 11타일 간격으로
솎아냈다 (297 → 143). 시작 위치 8개와 인트로 카메라(`086`)는 요새 바로 위로 옮겼다.

CHK 섹션 순서와 MASK(전장의 안개) 값은 원본과 바이트 단위로 같게 맞췄다.

## 3. 검증

`make.py` 가 매번 돌리는 자동 검사다.

- 미니타일 단위 통행 그래프에서 `hp1` 로부터 BFS → **모든 스폰 로케이션이 도달 가능**
- 원본에서 격리된 26곳은 격리 상태 유지 확인
- 메뉴룸 내부에서 `player1` → `m1`~`m5`, `fast`, `01` 전부 도보 도달 확인
- 보스 아레나 내부에서 `T4` → `xen`, `102`, `103` 전부 도달 확인
- 트리거가 참조하는 로케이션 중 빈 사각형이 없는지 확인
- **트리거가 세는 유닛 34종**에 대해, 원본에서 어느 로케이션 안에 몇 개 있었는지와
  새 맵의 개수를 대조 (`tools/unit_diff.py`). 모자란 만큼은 가장 가까운 같은 종류
  유닛을 그 로케이션 안으로 옮겨 채운다.

현재 결과: **문제 0건, 방 검사 PASS, 유닛 대조 PASS.**
시드 5·7·13·17·19·21·29·31·37·41 을 전부 돌려 모두 통과하는 것도 확인했다.

외부 검증으로 `tepc.exe`(TrigEditPlus 3.0 헤드리스 컴파일러)가 이 맵을 열어
MPQ → CHK 33개 섹션 → 트리거 1663개를 정상 파싱하는 것까지 확인했다.

## 4. 원본과 달라진 점

1. **이동 거리가 79%로 줄었다.** 원본 최대 1157 미니타일 → 새 맵 914.
   웨이브가 원본보다 약 1.25배 빨리 도착한다. 시드마다 0.60~0.83 사이로 갈리니
   여러 개 뽑아 비교하면 된다 (기본 17은 거리 0.79 + 개방 면적 43% 조합).
2. **유닛 밀도가 약 4배다.** 맵 면적이 1/4 인데 트리거가 뿜는 유닛 수는 그대로다.
   통행 가능 면적 비율은 원본(42%)과 같게 맞췄지만 절대 면적은 1/4 이므로,
   길목이 붐비면 웨이브당 생성 수를 줄이는 쪽으로 트리거를 손봐야 할 수도 있다.
   (`CreateUnit` 액션의 개수 인자만 건드리면 된다.)
   더 조절하고 싶으면 `tools/arena.py` 의 `self.rings` / `self.ring_gaps` 를 만지고
   `python tools/sweep.py` 로 비교하면 된다.
3. **적이 여러 방향에서 동시에 오는 느낌이 조금 줄고, 길목이 생겼다.**
   능선 통로가 병목 역할을 한다.
4. 스프라이트(THG2)와 원본 두들레드(DD2)는 좌표가 무의미해져 버리고 새로 깔았다.
5. 맵 이름과 지형 크레딧을 바꿨다. **게임 로직 제작자(픽시브) 표기는 그대로 뒀다.**

### ISOM 인코딩 (이 작업에서 역추적한 것)

ISOM 섹션은 `(w/2+1) x (h+1)` 개 셀, 셀당 u16 4개 `(left, top, right, bottom)`.
셀 `(ix,iy)` 는 타일 `(2*ix, iy)` 와 `(2*ix+1, iy)` 를 담당한다.

```
값 = 0                      (지형 타입이 0 일 때)
값 = (지형타입 << 4) | 모양   (그 외)
모양은 (ix+iy) 홀짝만으로 정해진다:
    짝수 → left=8, top=10, right=0,  bottom=2
    홀수 → left=4, top=12, right=14, bottom=6
```

이웃 셀은 **맞닿은 면의 지형 타입을 공유**한다
(`cell(ix,iy).right == cell(ix+1,iy).left`, `cell(ix,iy).bottom == cell(ix,iy+1).top`).
공식 맵 47개에서 이 공유 규칙은 **100.0000% 성립**했다.

그래서 지형은 "격자 변마다 지형 타입 하나"라는 필드로 완전히 표현되고,
유효한 조합(공식 맵에서 실제로 나온 4-튜플)만 쓰도록 WFC 를 돌리면 항상
말이 되는 지형이 나온다. ISOM→MTXM 변환표는 공식 트와일라잇 맵에 대해
**98.4% 일치**(나머지는 건설 가능/불가 변형 선택 차이)로 검증했다.

타일셋이 요구하는 최소 간격도 실측했다: HIGH/WATER/MUD 는 서로 맞닿을 수 없고
**LOW 를 1셀만 사이에 두면 충분**하다 (`tools/sep_test.py`).
